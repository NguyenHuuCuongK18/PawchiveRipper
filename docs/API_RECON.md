# API compatibility notes

The public regression suite uses generated metadata and synthetic media. Earlier captured response files and their live identities have been removed from the current tree.

## Boundaries exercised by the tests

- API requests use `Accept: text/css`, omit credentials, validate the response structure and treat truncated JSON as retryable.
- Discord offsets advance by 150. A successful empty page ends discovery; metadata counts and short pages do not. Repeated pages produce an explicit gap.
- IDs remain strings, including large snowflakes and prefixed post IDs.
- Server navigation is derived from validated channel URLs and merged with API metadata; generated CSS classes are not selectors.
- Media tests validate bytes and detected formats rather than trusting filenames or MIME types. Preview and original identities remain separate.

The generated scenarios cover 32 messages with 57 attachments, 209 messages across two pages, empty channels and 65 navigation links including threads. These are test cases, not live-site availability measurements.

## Optional manual research

`npm run recon -- SERVER_ID CHANNEL_ID [CHANNEL_ID...]` and `node scripts/server-recon.mjs SERVER_ID` require explicit IDs and use isolated browser profiles. Captures go only under ignored `artifacts/recon/`. Do not commit live captures, request headers, cookies, account data or downloaded creator content.

`npm run fixtures:data` regenerates the public metadata/HTML fixtures without a network request. `npm run privacy:check` verifies their exact generated bytes and the approved asset digests.
