# Validation and privacy

`npm run release:check` runs the privacy guard, unit tests, type checking, build, nine isolated Chromium suites, packaging and exact package verification.

## Automated coverage

- General browser workflows: ZIP/folder saving, permissions, cleanup, restart and supported-site gating.
- Media compatibility, selected-post continuation, tolerant discovery and archive settings/extraction.
- Blocklist coexistence and duplicate/shared-file recovery.
- Automatic/bulk sync, persistent queues, edited text, monthly repost reuse and missing-file repair.
- First-sync permission filtering, direct user activation, retry/skip and byte-for-byte archive preservation.

Unit tests exercise creator-name/JSON/path guards, changed bytes during comparisons, resumable ranges, scope preservation and scheduler behavior. Browser tests use disposable profiles and private OPFS fixture folders. They do not use a personal browser profile or a user archive.

## Public fixtures

Metadata and HTML are generated by `scripts/make-test-fixtures.mjs`. The JPEG is original geometric artwork. Decoder samples contain generated text or licensed libarchive test data. The privacy guard checks exact generated metadata and approved asset hashes, and blocks private/generated paths and credential patterns. It prints finding locations, never matched secret values.

Live captures are not public fixtures. Optional research scripts require explicit IDs and write only ignored artifacts. See [fixture provenance](../tests/fixtures/README.md).

## Manual checks

Native OS chooser/permission dialogs, session-only permission retention and platform filesystem behavior remain manual smoke checks. Automated approval tests use real OPFS handles with controlled permission responses and assert that each request starts from a click.

No automated test claims an OS-level junction/reparse-point guarantee. [Release checks](RELEASE_CHECK.md) record the actual suites and builds validated.
