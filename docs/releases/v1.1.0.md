# Pawchive Ripper v1.1.0

A major sync update since v0.9.1, with a persistent creator library, automatic checks and bulk actions.

## Changes

- Connect an archive root read-only; only correctly named creator folders with valid archive history are registered.
- Keep creator connections after job/cache cleanup. Choose **Off**, **Check only** or **Auto sync**, with recent-post checks and weekly full scans.
- Use **Select all**, **Check selected**, **Sync selected** and **Stop**. Full sync repairs missing files even when recent posts have not changed.
- Use **Allow first-sync folders** to approve preloaded creator folders one at a time, without browsing again. Completed, unselected and already-authorized creators are skipped.
- Show short statuses and keep explanations under **Details**.
- Preserve exact duplicate handling for reposted rewards, stable output paths and single-post/subset scopes. Automatic/bulk sync keeps compressed originals.
- Strengthen creator-name, JSON identity and path checks; preserve conflicting extraction outputs and verify identities before permitted source removal.
- Resume supported large downloads using validated ranges and private checkpoints.
- Replace captured test metadata with generated fictional fixtures. Exclude browser profiles/captures from Git and add a privacy check to the release gate.

## Install or update

Download **pawchive-ripper-1.1.0.zip** and extract it into a permanent folder. Enable Developer mode on the browser extensions page, choose **Load unpacked**, and select the folder containing `manifest.json`.

For an existing installation, replace files in its existing folder, reload the extension and refresh the site tab. Keep that folder path to preserve local jobs and connections. Open **Creators & sync**, connect your archive root, select creators and approve first-sync folder access. Automatic sync is opt-in; bulk buttons also work with automatic sync off.

Use a supported Chromium browser with the File System Access API for folder saving. Keep permission tabs open while saving if access is session-only. Native OS prompts remain a manual smoke check. Application guards do not provide an independent OS-level junction/reparse-point sandbox.

The ZIP contains production files and license notices only. `SHA256SUMS.txt` provides its checksum; test data, captures and browser profiles are excluded.
